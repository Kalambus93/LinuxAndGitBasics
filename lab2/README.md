## 📌 Задание 1. Локальные и глобальные переменные среды

>[!info]
> Теория: Типы переменных
>- **Переменная среды (Environment):** Устанавливается через `export`, наследуется и может использоваться дочерними процессами и оболочками.
>- **Переменная оболочки (Shell):** Устанавливается простым присваиванием, видна только в текущей сессии, **не** наследуется дочерними процессами.
>- **Глобальная переменная:** Прописана в системных файлах, доступна всем пользователям системы и сохраняется после перезагрузки.

>[!warning]
>- _Важно:_ Локальные переменные и переменные оболочки стираются из памяти при закрытии терминала.

### 1. Просмотр переменных

```bash
set | less
```

### 2. Локальная переменная

```bash
MY_LOCAL_VAR="local_var_value"
echo $MY_LOCAL_VAR
```

>[!warning]
> Результат проверки
> Если открыть **новое** окно терминала и выполнить `echo $MY_LOCAL_VAR`, вывод будет пустым. Переменная живет только в том окне (процессе), где была создана.

### 3. Переменная оболочки (через конфигурационный файл)

Чтобы переменная создавалась автоматически при каждом запуске терминала для текущего пользователя:

```bash
echo 'MY_SHELL_VAR="shell_var_value"' >> ~/.bashrc
source ~/.bashrc
```

### 4. Глобальная переменная (для всех пользователей)

```bash
# Добавляем переменную в системный файл
echo 'MY_GLOBAL_VAR="global_var_value"' | sudo tee -a /etc/environment

# Проверяем, что запись прошла успешно
grep MY_GLOBAL_VAR /etc/environment
```

>[!warning]
> Важное примечание
> Изменения в `/etc/environment` вступают в силу только после **полного перелогинивания** (выхода из системы и входа заново) или перезагрузки.

## 👥 Задание 2. Пользователи, группы и права доступа

### 1. Просмотр групп текущего пользователя

```bash
groups
# или более подробно
id
```

### 2. Создание группы, директории и файла

```bash
sudo groupadd new_group
sudo gpasswd new_group

mkdir new_test_dir
echo "test text" > new_test_dir/test_file.txt
ls -l new_test_dir
```

### 3. Изменение прав и владельца

>[!tip]
> Структура прав доступа (`ls -l`)
> | Позиция | Символы | Категория | Описание |
> | :---: | :---: | :--- | :--- |
> | 1 | `-` или `d` | Тип | `-` файл, `d` директория, `l` ссылка |
> | 2-4 | `rwx` | **u**ser (Владелец) | Чтение, запись, выполнение |
> | 5-7 | `rwx` | **g**roup (Группа) | Чтение, запись, выполнение |
> | 8-10| `rwx` | **o**thers (Остальные)| Чтение, запись, выполнение |

```bash
# Запрещаем чтение, запись и исполнение для остальных (others)
chmod o-rwx new_test_dir/test_file.txt
ls -l new_test_dir/test_file.txt

# Меняем владельца на root, а группу на new_group
sudo chown root:new_group new_test_dir/test_file.txt
ls -l new_test_dir/test_file.txt
```

### 4. Проверка прав и добавление в группу

```bash
# Попытка записи (выдаст ошибку "Permission denied", так как мы не root и не в группе)
echo "test text 2" >> new_test_dir/test_file.txt

# Добавляем текущего пользователя в группу new_group
sudo usermod -aG new_group $USER
```

>[!example]
> Как применить изменения группы без перезагрузки
> По умолчанию изменения групп видны только после перелогинивания. Чтобы применить их мгновенно:
>
> 1. Установите пакет (если его нет): `sudo apt install util-linux-extra`
> 2. Выполните: `newgrp new_group` (может потребоваться ввести пароль группы, заданный ранее).

```bash
# Даем группе право на запись (w)
sudo chmod g+w new_test_dir/test_file.txt
ls -l new_test_dir/test_file.txt

# Теперь запись успешна
echo "User currently in the group" >> new_test_dir/test_file.txt
cat new_test_dir/test_file.txt
```

## 🔗 Задание 3. Символические ссылки и псевдонимы

>[!success]
> Best Practice
> Вместо изменения системных директорий (вроде `/usr/bin`), безопаснее создать свою папку и добавить её в `$PATH`.

### 1. Создание безопасной директории и ссылки

```bash
# Создаем личную папку для исполняемых файлов/ссылок
mkdir ~/my_bin

# Добавляем её в начало PATH (для текущей сессии)
export PATH="$HOME/my_bin:$PATH"
echo $PATH # Проверяем, что my_bin появилась в начале

# Создаем символическую ссылку
ln -s ~/new_test_dir/test_file.txt ~/my_bin/tf

# Проверяем, что система видит ссылку
which tf
```

### 2. Изменение прав и проверка доступа

```bash
# Убираем права у группы и остальных для самой ссылки (и целевого файла)
sudo chmod go-rwx ~/my_bin/tf

# Передаем права владельца исходного файла пользователю root
sudo chown root ~/new_test_dir/test_file.txt

# Проверяем доступ (должно быть "Отказано в доступе", так как мы не root)
cat ~/my_bin/tf
cat ~/new_test_dir/test_file.txt
```

### 3. Псевдонимы (Aliases)

```bash
# Создаем временный псевдоним
alias lr='ls -l'
lr new_test_dir/

# Сохраняем псевдоним навсегда в ~/.bashrc
echo "alias lr='ls -l'" >> ~/.bashrc  # Исправлено на ls -l для корректности
source ~/.bashrc # Обновляем конфигурации в текущей сессии
```

## Задание 4. Управление процессами. Мультиплексоры

### 1. Управление задачами (Jobs)

```bash
# Просмотр активных задач
jobs

# Запуск задачи в фоновом режиме (&)
sleep 5 &
jobs

# Запуск задачи на переднем плане и её отложение (приостановка)
sleep 6
# Нажимаем Ctrl + Z
# Задача переходит в статус "Остановлен" (Stopped)

# Возобновление задачи с передачей управления на активный терминал (на передний план)
fg

# Принудительное завершение всех задач sleep
killall sleep
```

>[!note] Сигнатуры задач в `jobs`
>
> - `[N]+` : Последняя запущенная/измененная задача (запускается по умолчанию при `fg` или `bg`).
> - `[N]-` : Предпоследняя задача.

### 2. Работа с терминальным мультиплексором `tmux`

```bash
# 1. Создаем первую сессию
tmux new-session -s session1
# Внутри сессии выполняем:
cat
# (Нажимаем Ctrl+B, затем D для отключения (detach), не закрывая сессию)

# 2. Создаем вторую сессию
tmux new-session -s session2
# Внутри выполняем:
echo "the second session"
# (Снова Ctrl+B, затем D для отключения)

# 3. Подключаемся к первой сессии и останавливаем cat
tmux attach -t session1
# Нажимаем Ctrl+C для остановки cat
# Отключаемся: Ctrl+B, затем D

# 4. Завершаем первую сессию полностью
tmux kill-session -t session1

# 5. Имитация разрыва соединения: закрываем окно терминала крестиком.

# 6. Открываем НОВОЕ окно терминала и подключаемся ко второй сессии
tmux attach -t session2

# 7. Выполняем произвольную команду (данные сохранились)
echo "blablabla"
ls -l
```
